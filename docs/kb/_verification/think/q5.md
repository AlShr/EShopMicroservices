# How is a basket cached?

## Answer

The basket uses a **cache-aside** flow keyed by `userName`:

1. `GetBasket` calls `cache.GetStringAsync(userName)` to look up the basket. [src-services-basket-basket-api-data-cachedbasketrepository-cs]
2. On a cache hit, the JSON string is deserialized into a `ShoppingCart` and returned without querying the underlying repository. [src-services-basket-basket-api-data-cachedbasketrepository-cs]
3. On a cache miss, the basket is loaded from the repository, serialized to JSON, and stored with `cache.SetStringAsync(userName, ...)` before being returned. [src-services-basket-basket-api-data-cachedbasketrepository-cs]
4. The service configures a Redis connection at `localhost:6379`, while Docker exposes the `distributedcache` service on port 6379. [src-services-basket-basket-api-appsettings-json] [src-docker-compose-override-yml]

No expiration policy is supplied in the shown `SetStringAsync` call. [src-services-basket-basket-api-data-cachedbasketrepository-cs]

Basket deletion currently calls `repository.DeleteBasket(...)`, but its handler still contains a TODO to delete from both the database and cache, so cache invalidation on deletion is not demonstrated here. [src-services-basket-basket-api-basket-deletebasket-deletebaskethandler-cs]
